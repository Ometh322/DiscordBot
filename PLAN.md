# План: Discord-бот «Gachi Music Bot» (VK)

## 1. Функциональные требования

### 1.1 Поиск и воспроизведение GACHI-музыки из ВК
- Источник музыки — **аудиозаписи ВКонтакте** (не YouTube).
- Команда `/gachi <запрос>` (или `!gachi <запрос>`): бот ищет через VK API и отбирает треки, в названии или исполнителе которых есть `GACHI` или `ГАЧИ` (без учёта регистра).
- Найденный трек ставится в очередь и воспроизводится в голосовом канале, где находится автор команды (бот подключается следом).
- Управление плеером: `skip`, `stop`, `pause`/`resume`, `queue`, `leave`, том.

### 1.2 Случайный трек без повторов
- Команда `/gachi random [слово]`: бот выбирает трек **случайным образом**, при этом повторы минимизированы.
- Алгоритм «перемешанный мешок» (shuffle bag):
  1. при опустошении мешка — новый поиск в VK со случайными вариациями запроса (`gachi`, `gachi remix`, `гачи`, `gachimuchi` + опциональное слово от пользователя) и случайной страницей выдачи;
  2. результаты фильтруются по `GACHI|ГАЧИ` в названии и по наличию mp3-ссылки;
  3. из пула выкидываются треки из истории последних ~50 проигранных;
  4. пул перемешивается и хранится как очередь — пока не кончится, повторов гарантированно нет;
  5. каталог треков (id, название, исполнитель) накапливается в локальной базе — со временем «мешок» собирается из своей базы, а не только из свежего поиска.
- Режим `random` можно включить как автодиджей: `/gachi radio` — бот сам тянет следующий случайный трек, когда очередь пуста.

### 1.3 Звуковые реакции на вход в голосовой канал
- При подключении участника в голосовой канал бот проигрывает закреплённый за ним короткий звук (личный «саундтрек»).
- Привязка «пользователь → звук» настраивается командами: назначить файл, сбросить, список.
- Файл звука загружается прямо в чате (вложением) или кладётся в папку на сервере.
- Защита от спама: звук не проигрывается при перемещении между каналами/рконнектах чаще, чем раз в N секунд.

## 2. Технологический стек (рекомендация)

| Компонент | Выбор | Зачем |
|---|---|---|
| Язык | Python 3.9+ | discord.py, vk_api — готовые обёртки |
| Discord-обёртка | discord.py 2.5 (voice extra) | слэш-команды, голос, ивенты voice state; 2.6 не ставится на Win без Rust-тулчейна (davey) |
| Музыка из ВК | **vk_api + Kate-токен** (прямая авторизация, библиотека vkaudiotoken) | `audio.search`, `audio.getById` — поиск и прямые mp3-ссылки |
| Плеер | FFmpeg (`FFmpegPCMAudio`) | VK отдаёт готовую ссылку на mp3 — играем её напрямую |
| Голос | PyNaCl (входит в discord.py[voice]) + встроенный libopus | шифрование и кодирование голоса |
| Данные | SQLite (каталог треков, история) + JSON (привязки звуков) | статистика для «без повторов» |
| Конфиг | .env | DISCORD_TOKEN, VK_TOKEN, VK_USER_AGENT, VK_API_VERSION |

## 3. Подготовка

### 3.1 Discord (Developer Portal)
1. Создать приложение → добавить бота, скопировать **токен** (в `.env`, в git не коммитить).
2. Включить **Privileged Gateway Intents**:
   - Server Members Intent (для приветственных звуков),
   - Voice States Intent (обязательно),
   - Message Content Intent (если будут префиксные команды; для слэш-команд не нужен).
3. Ссылка-приглашение с правами: `View Channels`, `Send Messages`, `Connect`, `Speak`, `Embed Links`.
4. Установить на машину с ботом: Python, **FFmpeg** (уже поставлен через winget).

### 3.2 ВКонтакте
1. Завести **выделенный аккаунт ВК** для бота (не личный — риск бана аккаунта при автоматизации).
2. Получить **Kate-токен** (методы `audio.*` видны только таким): `scripts/get_vk_token.py` — прямая авторизация `grant_type=password` под клиентом Kate Mobile, с проверкой доступа к `audio.search` и, при необходимости, полным «андроид-флоу» через vkaudiotoken (GCM-чекин + auth.refreshToken). Скрипт сам сохраняет в `.env`: токен, User-Agent клиента Kate (обязателен при запросах) и рабочую версию API.
   - Токен из браузерного VK ID-флоу не подходит — ВК его методы `audio.*` не видит (проверено).
   - При ошибке «Flood control» (блок по IP из-за неудачных попыток): запустить через другой IP (`--proxy …`, мобильный интернет, VPN) или подождать ~24 ч.
3. На случай протухания токена — понятная ошибка в логах и повторный запуск скрипта.

## 5. Этапы разработки

### Этап 0 — Каркас ✅ (готово)
- venv (Python 3.9), зависимости, `.env`, `bot.py`, слэш-команды, FFmpeg (winget).
- Скрипты токенов; Discord-токен получен. Kate-токен: скрипт готов, ожидается успешный запуск после снятия Flood control.

### Этап 1 — Музыка из ВК ✅ (код готов, ждёт Kate-токен для живой проверки)
1. Cog `music`: `/gachi`, `/skip`, `/stop`, `/queue`, `/leave`.
2. `services/vk.py`: `audio.search` + фильтр `GACHI|ГАЧИ`, `audio.getById` для свежей ссылки перед проигрыванием, треки без `url` отбрасываются, понятные ошибки.
3. `services/player.py`: очередь на гильдию, `FFmpegPCMAudio(url)` с автопереподключением, автовыход из пустого канала через 5 минут.
4. UX: `defer()` + embed с названием/исполнителем/длительностью; запасной поиск `<запрос> gachi`.
5. Проверка: `scripts/test_music_core.py` (поиск → ссылка → декод 3 c в FFmpeg).

### Этап 2 — Случайный выбор без повторов (1 день)
1. SQLite: таблица `tracks` (каталог) и `plays` (история с временем).
2. `services/shuffle.py`: shuffle bag — случайный запрос/страница, фильтры, исключение последних ~50 проигранных, перемешанный пул на гильдию.
3. Команды `/gachi random [слово]` и `/gachi radio` (автодиджей).
4. Новый трек из любого поиска тоже попадает в каталог — база растёт сама.

### Этап 3 — Приветственные звуки (1 день)
1. Cog `welcome`: слушатель `on_voice_state_update`, детект «вошёл» (был None → стал канал).
2. Команды: `/sound set` (вложение), `/sound remove @user`, `/sound list`, `/sound test`.
3. `bindings.json`: `{guild_id: {user_id: "sounds/user_xxx.mp3"}}`.
4. Логика: бот в канале и музыка не играет → звук сразу; играет музыка → не прерывать (опция); бота нет в канале → ничего.
5. Антиспам: cooldown ~30 сек на пользователя, игнор ботов.

### Этап 4 — Полировка (0.5–1 дня)
- Обработка ошибок, кулдауны, права (`stop` только для тех, кто в войсе), логирование в файл, грациозное завершение.

### Этап 5 — Запуск и эксплуатация (0.5 дня)
- Windows: автозапуск через Планировщик задач или NSSM. VPS: systemd/Docker.
- `/status` (аптайм, размер каталога, остаток в «мешке»).

## 6. Риски и нюансы

- **Kate-токен — единственный вход на аудио-методы**; ВК может менять правила (Flood control, блокировки прямой авторизации). Запасной путь — токен Boom (implicit flow) из PHP-библиотеки vk-audio-token.
- **Риск для аккаунта ВК**: автоматизация нарушает правила ВК; только выделенный аккаунт.
- **Протухающие ссылки**: mp3-URL живут ограниченное время → в базе храним id, URL обновляем перед проигрыванием.
- **Правообладатели**: часть треков без `url` — фильтруются.
- **Rate limit** `audio.search`: запросы идут нечасто, при массовых операциях нужны паузы.
- **FFmpeg**: путь зафиксирован в `.env` (winget-установка вне PATH).

## 7. Ориентир по трудозатратам

Всего: **~4–6 дней** чистой работы для MVP (Этапы 0–3), ещё 1–2 дня на полировку и деплой.
