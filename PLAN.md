# План: Discord-бот «Gachi Music Bot» (SoundCloud)

## 1. Функциональные требования

### 1.1 Поиск и воспроизведение GACHI-музыки
- Источник музыки — **SoundCloud** (после закрытия ВК аудио-API в 2026 токены Kate/Boom/VK недоступны).
- Команда `/gachi <запрос>`: поиск через yt-dlp (`scsearch`), отбор треков с `GACHI`/`ГАЧИ` в названии или исполнителе (без учёта регистра).
- Трек ставится в очередь и играет в голосовом канале автора (бот подключается следом).
- Управление: `skip`, `stop`, `queue`, `leave` (+ `pause`/`resume`, том — полировка).

### 1.2 Случайный трек без повторов
- `/gachi random [слово]` — случайный трек, повторы минимизированы (shuffle bag):
  1. при опустошении мешка — новый поиск со случайными вариациями запроса (`gachi`, `gachi remix`, `гачи`, `gachimuchi` + слово) и случайной страницей выдачи;
  2. фильтр по `GACHI|ГАЧИ` и наличию потока;
  3. исключение последних ~50 проигранных;
  4. пул перемешивается — до исчерпания повторов нет;
  5. каталог треков копится в SQLite — «мешок» со временем собирается из своей базы.
- `/gachi radio` — автодиджей: пустая очередь → сам тянет случайный трек.

### 1.3 Звуковые реакции на вход в голосовой канал
- При входе участника — его личный короткий звук.
- Привязки командами (`/sound set` вложением, `/sound remove`, `/sound list`), хранение JSON.
- Антиспам: cooldown ~30 с, игнор перемещений между каналами.

## 2. Технологический стек

| Компонент | Выбор | Зачем |
|---|---|---|
| Язык | Python 3.9 (желательно 3.10+ — yt-dlp объявил 3.9 устаревшим) | актуальные библиотеки |
| Discord | discord.py 2.5 [voice] | слэш-команды, голос; 2.6 требует Rust (davey) на Win |
| Музыка | **yt-dlp** (`scsearch`, экстракция потока) | SoundCloud без токенов и регистраций |
| Плеер | FFmpeg (`FFmpegPCMAudio`) | HLS/progressive-потоки SoundCloud напрямую |
| Данные | SQLite (каталог/история) + JSON (привязки звуков) | статистика «без повторов» |
| Конфиг | .env | DISCORD_TOKEN, FFMPEG_PATH — и всё |

Ключевое преимущество перед ВК-вариантом: **никаких токенов** — yt-dlp работает с публичным веб-клиентом SoundCloud и поддерживает его годами.

## 3. Подготовка

### 3.1 Discord (Developer Portal)
1. Приложение → Bot → токен в `.env` (DISCORD_TOKEN).
2. Privileged Gateway Intents: Server Members (для звуков), Voice States; Message Content не нужен.
3. Приглашение с правами: View Channels, Send Messages, Connect, Speak, Embed Links.

### 3.2 SoundCloud
Ничего не нужно. Зависимость `yt-dlp` ставится из requirements.txt; при поломках (SoundCloud меняет клиент) — обновить `pip install -U yt-dlp`.

### Этап 0 — Каркас ✅

### Этап 1 — Музыка ✅ (проверено живьём 2026-09-08)
- `services/soundcloud.py`: `search()` с фильтром GACHI/ГАЧИ, `fresh_url()` перед каждым треком (подписи SoundCloud протухают), ошибки по-русски.

### Этап 3 — Приветственные звуки (1 день)

### Этап 4 — Полировка (0.5–1 дня)

## 6. Риски и нюансы

- **SoundCloud меняет веб-клиент** → лечится `pip install -U yt-dlp` (регулярно обновляется).
- **Не все треки стримятся** (гео/правообладатель) → отбраковываются с сообщением, очередь идёт дальше.
- **Python 3.9** объявлен yt-dlp устаревшим (пока работает) → при случае обновить до 3.10+.
- **ToS**: стриминг SC в Discord — серая зона, как у всех музыкальных ботов.
- Часть треков только в HLS (m3u8) — FFmpeg стримит напрямую, проверено.
