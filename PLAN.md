# План: Discord-бот «Gachi Music Bot» (SoundCloud)

## 1. Функциональные требования

### 1.1 Поиск и воспроизведение GACHI-музыки
- Источник музыки — **SoundCloud** (после закрытия ВК аудио-API в 2026 токены Kate/Boom/VK недоступны).
- Команда `/gachi язык:ru|ang количество:1-10`: случайные треки в очередь. `ru` → поиск по запросам «гачи…», `ang` → «gachi…». Выборка случайная (вариации запроса + случайная страница выдачи), последние ~60 треков сервера не повторяются (пока в памяти; Этап 2 — SQLite).
- Трек играет в голосовом канале автора (бот подключается следом).
- Управление: слэш-команды `skip`, `stop`, `queue`, `leave` **+ панель кнопок под «Сейчас играет»**: ⏮ назад (история), ⏸/▶ пауза, ⏹ стоп, ⏭ скип. Кнопки доступны тем, кто в канале с ботом.

### 1.2 Случайный трек без повторов
- `/gachi random [слово]` — случайный трек, повторы минимизированы (shuffle bag):
  1. при опустошении мешка — новый поиск со случайными вариациями запроса (`gachi`, `gachi remix`, `гачи`, `gachimuchi` + слово) и случайной страницей выдачи;
  2. фильтр по `GACHI|ГАЧИ` и наличию потока;
  3. исключение последних ~50 проигранных;
  4. пул перемешивается — до исчерпания повторов нет;
  5. каталог треков копится в SQLite — «мешок» со временем собирается из своей базы.
- `/gachi radio` — автодиджей: пустая очередь → сам тянет случайный трек.

### 1.3 Звуковые реакции на вход в голосовой канал ✅
- Папка `data/sounds/` (с README внутри): любые аудиофайлы (mp3/ogg/wav/m4a/flac/opus), без привязки к юзерам.
- Участник зашёл в канал или `/hello` → играет **случайный** файл из папки.
- Если играла музыка — она **приостанавливается** (трек и очередь не двигаются), после приветствия трек возобновляется.
- Если бота не было в канале — подключается следом и уходит после; кулдаун 30 с на участника; перемещения игнорируются.

## 2. Технологический стек

| Компонент | Выбор | Зачем |
|---|---|---|
| Язык | Python 3.12 (окружение пересоздано с 3.9) | актуальные библиотеки |
| Discord | discord.py 2.7 [voice] (+davey, готовая сборка на 3.12) | слэш-команды, голос, **DAVE/E2EE** — Discord требует его для войса (код 4017) |
| Музыка | **yt-dlp** (`scsearch`, экстракция потока) | SoundCloud без токенов и регистраций |
| Плеер | FFmpeg (`FFmpegPCMAudio`) | HLS/progressive-потоки SoundCloud напрямую |
| Данные | SQLite (каталог/история) + JSON (привязки звуков) | статистика «без повторов» |
| Конфиг | .env | DISCORD_TOKEN, FFMPEG_PATH — и всё |

Ключевое преимущество перед ВК-вариантом: **никаких токенов** — yt-dlp работает с публичным веб-клиентом SoundCloud и поддерживает его годами.

## 3. Подготовка

### 3.1 Discord (Developer Portal)
1. Приложение → Bot → токен в `.env` (DISCORD_TOKEN).
2. Privileged Gateway Intents: Server Members (для звуков), Voice States; Message Content не нужен.
3. Приглашение с правами: View Channels, Send Messages, Connect, Speak, Embed Links.

### 3.2 SoundCloud
Ничего не нужно. Зависимость `yt-dlp` ставится из requirements.txt; при поломках (SoundCloud меняет клиент) — обновить `pip install -U yt-dlp`.

## 5. Этапы

### Этап 0 — Каркас ✅
venv, FFmpeg (winget), .env, токен Discord, /ping.

### Этап 1 — Музыка ✅ (проверено живьём 2026-09-08)
- `services/soundcloud.py`: `search()` с фильтром GACHI/ГАЧИ, `fresh_url()` перед каждым треком (подписи SoundCloud протухают), ошибки по-русски.
- `services/player.py`: очередь на гильдию, `FFmpegPCMAudio` с автопереподключением, автовыход через 5 минут простоя.
- `cogs/music.py`: `/gachi` (+fallback `<запрос> gachi`), `/skip`, `/stop`, `/queue`, `/leave`; embed с названием/исполнителем/длительностью.
- Живой тест `scripts/test_music_core.py`: 20 GACHI-треков найдено, HLS-поток декодирован FFmpeg — OK.

### Этап 2 — Случайный выбор без повторов (1 день)
SQLite (`tracks`, `plays`), `services/shuffle.py`, команды `/gachi random` и `/gachi radio`.

### Этап 3 — Приветственные звуки ✅ (упрощённый вариант)
`cogs/welcome.py`: вход в войс → персональный файл из `data/sounds/` (по id/логину/имени), автоподключение и автовыход, без прерывания музыки, кулдаун 30 с; команда `/hello`. Управление файлами — просто копированием в папку.

### Этап 4 — Полировка (0.5–1 дня)
Ошибки, кулдауны, права, лог в файл, pause/resume, том.

### Этап 5 — Эксплуатация (0.5 дня)
Автозапуск Windows (Планировщик/NSSM) или VPS, `/status`.

## 6. Риски и нюансы

- **SoundCloud меняет веб-клиент** → лечится `pip install -U yt-dlp` (регулярно обновляется).
- **Не все треки стримятся** (гео/правообладатель) → отбраковываются с сообщением, очередь идёт дальше.
- **Python 3.9** объявлен yt-dlp устаревшим → окружение пересоздано на Python 3.12 (2026-09-08).
- **ToS**: стриминг SC в Discord — серая зона, как у всех музыкальных ботов.
- Часть треков только в HLS (m3u8) — FFmpeg стримит напрямую, проверено.

## 7. Ориентир по трудозатратам

MVP (Этапы 0–3): ~3–5 дней; полировка и деплой: ещё 1–2 дня.
